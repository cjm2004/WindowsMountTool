# 云盘挂载向导项目目录说明

本文档说明 `winmount` 项目当前整理后的目录结构、各目录的用途、维护边界和常用操作。目录说明以当前实际文件为准，重点区分现行 Python/Tkinter 构建链、早期 PowerShell/NSIS 构建链、运行数据以及历史归档内容。

## 一、项目定位

本项目是一个 Windows x64 云盘挂载工具，核心工作链路如下：

```text
Alist / OpenList
        │ WebDAV
        ▼
     rclone
        │ WinFsp 文件系统
        ▼
Windows 本地盘符
```

项目包含两个主要程序：

- `CloudMountSetup.exe`：安装程序，负责安装主程序、释放运行资源、安装 WinFsp、创建快捷方式和注册卸载项。
- `mount_wizard.exe`：配置向导和控制台，负责配置网盘、启动 Alist、调用 rclone 挂载，以及管理开机自启和健康检查。

当前正式界面保留旧版 Tkinter 风格，并在原有界面基础上增加了驱动状态、安装入口、主题切换、关于页面等功能。

## 二、根目录结构

整理后的根目录只放正式成品、项目入口文件和主要分类目录，结构大致如下：

```text
winmount/
├─ CloudMountSetup.exe       # 正式安装器
├─ mount_wizard.exe          # 正式配置向导
├─ README.md                 # 项目简要说明和历史构建提示
├─ build.ps1                # 旧版 PowerShell/NSIS 构建入口
├─ py_src/                  # 现行安装器 Python 源码
├─ py_src_wizard/           # 现行配置向导 Python 源码
├─ source/                  # 旧版 PowerShell/NSIS 源码链
├─ dist/                    # NSIS/PowerShell 链构建输出和发布资源
├─ tools/                   # 本地构建工具及安装依赖
├─ runtime/                 # 本机运行测试数据和运行时文件
├─ tests/                   # 安装、挂载、卸载和诊断脚本
├─ logs/                    # 构建、测试和审查日志
├─ docs/                    # 项目文档
├─ _archive/                # 历史版本、分析文件和构建缓存
└─ .workbuddy/              # 本项目工作记忆和会话辅助数据
```

根目录下的两个 EXE 是用户优先使用的正式成品。修改源码后，不应手动修改 EXE；应从对应源码重新构建，再将经过验证的成品同步到根目录。

## 三、正式成品

### 1. `CloudMountSetup.exe`

正式安装器。双击后进入安装界面，主要职责包括：

- 选择并校验安装目录。
- 释放 `mount_wizard.exe`。
- 释放 WinFsp 安装包。
- 启动主程序初始化运行时资源。
- 配置运行目录权限。
- 创建桌面和开始菜单快捷方式。
- 写入 Windows 控制面板卸载项。
- 在升级场景下处理旧的计划任务和残留进程。

该文件是最终交付给普通用户的安装入口。发布前应至少确认它具备合法的 Windows `MZ` 头，并完成安装、启动和卸载测试。

### 2. `mount_wizard.exe`

正式配置向导。安装完成后由用户启动，主要职责包括：

- 首次启动时显示分步配置向导。
- 已有配置时进入挂载管理控制台。
- 配置 WebDAV、Alist/OpenList 和中国移动网盘等远端。
- 管理多个挂载配置和本地盘符。
- 启动或停止 Alist 与 rclone。
- 通过 WinFsp 创建 Windows 本地盘符。
- 管理开机自启和健康检查计划任务。
- 显示日志、驱动状态和运行状态。
- 提供暗色/亮色主题切换和“关于”页面。

不要把 `mount_wizard.exe` 当作普通压缩包解压或手动替换内部文件。它是由 PyInstaller 打包的单文件程序，内部资源会在首次运行时释放到安装目录的 `runtime` 中。

## 四、现行 Python 源码目录

### 1. `py_src/`

这是当前安装器的主要 Python 源码目录，负责构建 `CloudMountSetup.exe`。

```text
py_src/
├─ installer.py             # 安装器 Tkinter 界面和安装逻辑
├─ ui_theme.py              # 安装器共用主题模块
├─ CloudMountSetup.spec     # PyInstaller 安装器打包配置
├─ uninstaller.py           # 卸载程序源码
├─ uninstall.spec           # 卸载程序打包配置
├─ test_ui.py               # 安装器界面测试辅助脚本
├─ icon.ico                 # 安装器图标
├─ payload/                 # 安装器内嵌资源
│  ├─ mount_wizard.exe
│  ├─ winfsp.msi
│  └─ THIRD_PARTY_NOTICES.txt
└─ dist/                    # 当前或最近一次 PyInstaller 输出
```

维护规则：

- `installer.py` 是安装器界面和安装流程的主要修改入口。
- `ui_theme.py` 的修改会影响安装器界面，应同步检查深色和浅色主题。
- `CloudMountSetup.spec` 决定安装包内嵌哪些资源，新增资源时必须同步更新该文件。
- `payload/mount_wizard.exe` 是安装器内嵌的主程序副本。重新构建挂载向导后，必须先更新该副本，再构建安装器。
- `payload/winfsp.msi` 是 WinFsp 安装资源，不要随意替换为来源不明的安装包。
- `py_src/dist/` 是构建输出目录，不是手工编辑目录。

### 2. `py_src_wizard/`

这是当前配置向导的主要 Python 源码目录，负责构建 `mount_wizard.exe`。

```text
py_src_wizard/
├─ app.py                    # 配置向导、控制台和挂载逻辑
├─ ui_theme.py               # 配置向导共用主题模块
├─ mount_wizard.spec         # PyInstaller 挂载向导打包配置
├─ icon.ico                 # 挂载向导图标
├─ payload/                  # 挂载向导内嵌运行资源
│  └─ source/
│     ├─ tools/              # Alist 和 rclone
│     ├─ config/             # 默认 rclone 配置模板
│     └─ assets/             # 关于页二维码等图片资源
└─ dist/                    # 当前或最近一次 PyInstaller 输出
```

`app.py` 负责的功能范围较大，包括运行时目录准备、远端配置、Alist 管理、rclone 调用、WinFsp 盘符检测、挂载/卸载、计划任务和关于页面。修改后应重点验证：

- 远端名称是否带结尾冒号，例如 `cloud_xxx:`。
- `rclone.conf` 是否以无 BOM 的 UTF-8 写入。
- 挂载成功是否以真实盘符检测为准。
- Alist 管理接口是否使用 `/api/admin/` 前缀。
- WinFsp 安装或升级后，驱动是否已经加载。
- 深色/浅色主题和关于页两张图片是否正常显示。

### 3. 两个源码目录之间的关系

构建顺序通常是：

```text
py_src_wizard/app.py
        │
        ├─ PyInstaller
        ▼
py_src_wizard/dist/mount_wizard.exe
        │
        ├─ 复制到 py_src/payload/
        ▼
py_src/installer.py + payload
        │
        ├─ PyInstaller
        ▼
py_src/dist/CloudMountSetup.exe
        │
        └─ 验证后同步到根目录 CloudMountSetup.exe
```

因此，先构建安装器再构建挂载向导，或者只更新向导而不更新安装器 payload，都可能造成最终安装包仍内嵌旧版本主程序。

## 五、旧版 PowerShell/NSIS 源码目录

### `source/`

`source/` 是项目早期的 PowerShell/WPF 或 NSIS 构建链，保留用于参考、兼容和历史维护，不是当前 Python/Tkinter 界面的主要源码目录。

```text
source/
├─ Installer.ps1              # 早期 PowerShell 安装入口
├─ ConfigApp.ps1              # 早期 PowerShell 配置界面
├─ ConfigApp.cmd              # 配置程序启动脚本
├─ installer.nsi              # NSIS 安装器脚本
├─ launcher.nsi               # 主程序启动器脚本
├─ icon.nsi                   # 图标资源脚本
├─ _icon_path.nsh             # NSIS 图标路径辅助文件
├─ icon.ico                   # NSIS/启动器图标
├─ bin/CloudMount.exe         # NSIS 启动器输出
├─ scripts/                   # 早期挂载、任务和卸载脚本
└─ tools/                     # 早期链路使用的 Alist 和 rclone
```

其中 `source/scripts/` 包含：

- `mount.ps1`：挂载和卸载核心脚本。
- `watchdog.ps1`：健康检查和自愈逻辑。
- `tasks.ps1`：计划任务注册和管理。
- `autostart.ps1`：开机自启处理。
- `uninstall.ps1`：旧版卸载逻辑。

维护注意：

- 不要把 `source/` 与 `py_src/`、`py_src_wizard/` 的文件混合覆盖。
- `build.ps1` 默认调用的是 `source/installer.nsi`，属于旧版 NSIS 构建入口。
- 如果目标是重建当前正式 Tkinter 安装器，应使用 `py_src/` 的 PyInstaller 配置，并同步挂载向导 payload。
- `.ps1` 和 `.nsi` 文件对编码、换行和 BOM 较敏感；修改旧链时必须保留项目既有格式约束。

## 六、发布和构建目录

### 1. `dist/`

`dist/` 是根目录下的发布/构建输出目录，当前可见内容包括：

- `CloudMountSetup.exe`：安装器输出副本。
- `CloudMountSetup_noicon.exe`：历史或测试用的无图标版本。
- `._cache_CloudMountSetup_noicon.exe`：构建过程产生的缓存或临时文件。
- `ConfigApp.ps1`、`ConfigApp.cmd` 和 `scripts/`：旧版安装目录布局文件。
- `tools/`：Alist、rclone 和 WinFsp MSI 等发布资源。

该目录同时承载过不同阶段的 NSIS/PowerShell 输出，不能仅凭目录名判断其中每个 EXE 都是当前正式版本。发布前应以文件哈希、构建时间和实际功能测试确认版本；正式交付优先使用根目录已验证的 `CloudMountSetup.exe`。

### 2. `py_src/dist/`

安装器 Python 构建输出目录，主要放 PyInstaller 生成的 `CloudMountSetup.exe` 和卸载程序输出。该目录可以清理后重新构建，但清理前应确认没有正在运行的程序或正在使用的文件。

### 3. `py_src_wizard/dist/`

挂载向导 Python 构建输出目录，主要放 PyInstaller 生成的 `mount_wizard.exe` 及其运行时资源。构建完成后，需将经过测试的 `mount_wizard.exe` 同步到安装器的 `py_src/payload/`，再重新构建安装器。

## 七、工具和依赖目录

### 1. `tools/`

本地构建和测试所需的工具目录，当前包括：

- `winfsp-2.1.25156.msi`：WinFsp 安装包。
- `resource_hacker.zip`：Resource Hacker 压缩包。
- `ResourceHacker/`：Resource Hacker 工具及帮助、示例文件。

该目录用于开发和构建，不等同于用户安装后的运行目录。不要把临时测试生成的配置文件、账号令牌或个人数据放入这里。

### 2. 程序运行时工具

Alist 和 rclone 在不同构建链中的位置不同：

- 当前 Python 挂载向导的内嵌源资源：`py_src_wizard/payload/source/tools/`。
- 当前安装器的内嵌挂载向导资源：`py_src/payload/mount_wizard.exe`。
- 旧版 NSIS 链的资源：`source/tools/` 或 `dist/tools/`。
- 实际运行目录：安装位置下的 `runtime/tools/`。

修改 Alist 或 rclone 版本时，不能只替换其中一个位置。应明确目标构建链，并在最终安装、启动和挂载测试中确认实际使用的是哪个副本。

## 八、运行和测试目录

### 1. `runtime/`

本项目工作区中的本机运行时测试目录，通常包含：

```text
runtime/
├─ tools/                    # 测试时释放的 alist.exe、rclone.exe
└─ config/                   # 测试时使用的 rclone.conf
```

正式安装后，类似结构会出现在安装目录或用户可写的运行目录中，并可能继续生成：

- `config/`：远端配置和 rclone 配置。
- `data/`：程序状态、维护开关等运行数据。
- `logs/`：运行日志。
- `tools/`：Alist、rclone 等工具。
- `scripts/`、`docs/`：随程序释放的脚本和说明。

`runtime/` 可能包含账号、令牌、加密配置或测试数据，不应提交到公共代码仓库，也不应随意覆盖。特别是 `config/rclone.conf`，即使密码经过 obscure 处理，也应按敏感配置管理。

### 2. `tests/`

自动化和半自动化测试脚本目录：

- `01_install.ps1`：安装测试。
- `02_mount.ps1`：挂载测试。
- `03_uninstall.ps1`：卸载测试。
- `diag_mount.ps1`：挂载故障诊断。
- `probe_alist_api.ps1`：Alist 接口探测。
- `comprehensive_test.ps1`：综合测试。
- `full_functional_test.ps1`：完整功能测试。

测试脚本可能安装 WinFsp、创建计划任务、启动 Alist/rclone、修改盘符和写入运行目录。执行前要确认测试目标目录，不要在正在使用的正式安装目录上直接运行破坏性测试。

### 3. `logs/`

构建、测试、诊断和代码审查日志目录。常见内容包括：

- `build*.log`、`pyinstaller*.log`：构建日志。
- `install-run.log`、`mount-run.log`、`uninstall-run.log`：安装、挂载和卸载运行日志。
- `test-*.txt`、`*_test.log`：测试记录。
- `FINAL_TEST_REPORT.md`：功能测试报告。
- `CODE_REVIEW_2026-09-12.md`：代码审查报告。

日志通常可以用于追溯问题，但可能包含本机路径、盘符、接口返回内容或配置相关信息。对外分享前应检查并脱敏。新的测试报告和构建日志应继续放入 `logs/`，不要堆到根目录。

## 十、历史归档目录

### `_archive/`

`_archive/` 保存历史版本和已经退出当前工作链的过程文件。其内容原则上只读，不作为当前构建输入。

```text
_archive/
├─ analysis/                         # 字节码分析、反编译和问题定位资料
├─ extracted/                        # 压缩包或程序解包内容
├─ CloudMountSetup.exe_extracted/    # 安装器解包目录
├─ mount_wizard.exe_extracted/       # 挂载向导解包目录
├─ old/                              # 旧版本程序
├─ dist-legacy/                      # 旧版发布输出
├─ build_cache/                      # 历史构建缓存
├─ CloudMountSetup.原始PyInstaller版.exe
├─ 云盘挂载本地盘工具包.zip
└─ 解压本压缩包，将指令复制给AIagent.zip
```

### `_archive/build_cache/`

该目录按来源分为：

- `_archive/build_cache/py_src/`：安装器历史 `build*`、`dist_*` 和 `__pycache__`。
- `_archive/build_cache/py_src_wizard/`：挂载向导历史 `build*`、`dist_*` 和 `__pycache__`。
- `_archive/build_cache/root/`：根目录历史 Python 缓存。

这些目录中的内容是可追溯的历史构建产物，不是当前源码。除非需要复盘旧版本或恢复旧构建结果，否则不应从这里复制文件覆盖现行源码或正式成品。

### `_archive/extracted/`

保存原始压缩包解压后的指令包和工具包，例如旧版 Alist、rclone、脚本、配置模板和排错资料。这里的 `rclone.conf` 可能是示例或历史配置，不能直接当作当前用户配置使用。

### `_archive/*_extracted/`

保存通过 PyInstaller 或其他工具解包得到的内部文件，主要用于分析旧版程序的资源组成和行为。它们不是可直接运行的正式安装目录，也不应作为新的打包输入。

## 十一、`.workbuddy/` 目录

### `.workbuddy/`

本项目的工作记忆和辅助数据目录，用于记录项目长期事实、每日工作日志和会话上下文。该目录不是构建缓存，也不是普通临时目录。

- 不要删除整个 `.workbuddy/`。
- 不要把账号密码、令牌等敏感信息写入工作记忆。
- 项目历史记录应追加到对应日期的日志文件，不要覆盖已有日志。

## 十二、哪些内容可以修改

### 通常可以直接修改

- `py_src/installer.py`
- `py_src/ui_theme.py`
- `py_src/CloudMountSetup.spec`
- `py_src_wizard/app.py`
- `py_src_wizard/ui_theme.py`
- `py_src_wizard/mount_wizard.spec`
- `docs/` 中的项目文档
- `tests/` 中与当前测试流程有关的脚本

修改 Python 源码后，至少应进行语法编译和针对受影响功能的测试。界面代码修改后应检查窗口启动、主题切换和页面切换。

### 修改前应确认构建链

- `source/` 下的 PowerShell 和 NSIS 文件。
- `build.ps1`。
- `dist/` 下的发布资源和 EXE。
- `tools/` 下的 WinFsp MSI、Resource Hacker 等工具。

这些文件可能属于旧链、兼容链或发布输入。修改前应先确认是否仍被当前构建流程使用。

### 不应直接编辑或覆盖

- 根目录的 `CloudMountSetup.exe`。
- 根目录的 `mount_wizard.exe`。
- `py_src/dist/` 和 `py_src_wizard/dist/` 中的构建输出。
- `_archive/` 中的历史产物。
- `runtime/config/` 中的真实或测试配置。
- `logs/` 中已经形成的历史记录。

## 十三、推荐构建流程

### 构建当前 Python/Tkinter 版本

1. 修改 `py_src_wizard/` 中的配置向导源码。
2. 使用对应的 PyInstaller 配置构建 `mount_wizard.exe`。
3. 验证挂载向导启动、主题切换、关于页、驱动检测和核心挂载功能。
4. 将经过验证的挂载向导复制到 `py_src/payload/mount_wizard.exe`。
5. 使用 `py_src/CloudMountSetup.spec` 构建 `CloudMountSetup.exe`。
6. 验证安装包能释放正确的主程序和 WinFsp 资源。
7. 完成安装、启动、挂载、卸载和副本哈希检查。
8. 将最终通过验收的安装器和挂载向导同步到根目录。

### 构建旧版 NSIS/PowerShell 版本

使用根目录的 `build.ps1`，它会检查 `source/` 和 `tools/` 下的构建输入并调用 NSIS。该流程生成的结果属于旧版构建链，不能默认认为与当前 Python/Tkinter 正式版本等价。

## 十四、发布前检查清单

- 根目录 `CloudMountSetup.exe` 和 `mount_wizard.exe` 均为最新验收版本。
- 安装器和挂载向导均能正常启动。
- WinFsp 安装状态检测正确，必要时提示重启。
- Alist、rclone 和 WinFsp 资源齐全。
- `rclone.conf` 无 BOM，远端名带结尾冒号。
- 挂载成功以真实盘符出现为准。
- 安装、升级、挂载、卸载和开机自启流程均已测试。
- 账号、密码、令牌和本机路径等日志内容已经检查，不会误发布。
- 正式 EXE 的哈希已记录，根目录、构建输出和 payload 副本没有混用旧版本。
- 历史缓存仍在 `_archive/`，没有被重新混入发布目录。

## 十五、目录整理原则

今后的新增文件遵循以下规则：

- 最终交付的 EXE 放根目录，并在对应构建目录保留一份经过验证的输出。
- Python 源码和打包配置放 `py_src/` 或 `py_src_wizard/`。
- 旧版 PowerShell/NSIS 代码继续放 `source/`，不要与现行 Python 源码混放。
- 构建、测试和审查记录放 `logs/`。
- 说明文档放 `docs/`。
- 历史版本、解包结果、原始压缩包和构建缓存放 `_archive/`。
- 运行配置和测试状态放 `runtime/`，不提交真实账号信息。
- 不在根目录随意创建新的临时目录或临时文件。
